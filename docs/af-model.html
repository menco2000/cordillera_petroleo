Cordillera Petróleo AF Model

Fictional oil & gas company with 8 metropolitan sites across South America. Each site has its own oil field and its own refinery. The hierarchy follows ISA-95 equipment levels, and the ISA-88 physical model names the refinery units. Every element and attribute below comes from model/spec.py, the same file that will generate the AF XML and drive the simulator.

1 · Structure

How a site is organized

Every site has the same structure. The only differences are the number of wells, their lift methods and the equipment sizing. The diagram follows the product from the wells to the product tanks. Swimlanes are ISA-95 areas, inner boxes are work centers (ISA-88 process cells), and nodes are work units and equipment modules.

Conventions

Tag name
CP.<SITE>.<ASSET>.<SUFFIX>, e.g. CP.LAG.W03.PIP. The prefix is stored in each element's Tag Prefix attribute, so the PI Point references are defined once on the template.
Units
Oilfield units: psig/psia, bbl/d, Mscf/d, °F. Vacuum in mmHg absolute.
Inheritance
Asset Base → Well → Well - ESP. Analysis and notification live on Well and reach all lift types.
No rollups
Field totals are simulator tags, not analyses, to keep the single-analysis rule.
ISA-88 use
ISA-88 is a batch standard and a refinery runs continuously. So we use its physical model names, and the Extraction Run event frame is the record of each production run.

6 · Simulator

Scenarios the simulator will produce

The simulator runs on your network. It backfills about 90 days of history, then keeps writing in real time through PI Web API. Variables are physically coupled, so cause and effect show up in the data. That is what you need for forecasting and pattern recognition.
